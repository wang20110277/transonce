# Frontend / Backend Separation — Design

- **Date:** 2026-06-15
- **Status:** Approved
- **Scope:** Restructure the repository so frontend (Vite + React + TypeScript) and backend (Python + FastAPI) code live in clearly separated directory trees within a single git repository.

## 1. Goal

Today the frontend lives at the repository **root** (`src/`, `components/`, `hooks/`, `lib/`, `index.html`, `vite.config.ts`, `tsconfig.json`, `package.json`) while the backend is nested in `server/`. This asymmetry mixes concerns: the root `package.json` even carries unused backend dependencies (`express`, `pg`).

The goal is a clean separation: move the frontend into its own folder (`client/`), leave the backend where it is (`server/`), and remove the dependency contamination — **without changing any source logic or backend behavior**.

## 2. Decisions (from brainstorming)

| Decision | Choice |
|---|---|
| Separation style | **In-repo folder split** (single git repo, two directory trees) |
| Folder names | **`client/` + `server/`** (backend `server/` is not renamed) |
| Dependency cleanup | **Prune unused backend deps** from the frontend `package.json` |

## 4. What moves into `client/`

The following are moved verbatim from the repository root into `client/`:

- `src/` (the React application)
- `components/` (shadcn UI components)
- `hooks/`
- `lib/`
- `index.html`
- `vite.config.ts`
- `tsconfig.json`
- `package.json`
- `package-lock.json`
- `components.json`

The `dist/` build output is **deleted**, not moved — it is gitignored and regenerated by `vite build`.

## 5. What stays / what does not change

- **`server/`** — location, code, Python dependencies, Alembic migrations, and the uvicorn run command are untouched.
- **Vite dev proxy** — `/api` → `http://localhost:8000` and `/asr` → `http://localhost:8001` point at absolute localhost ports and are unaffected by where the frontend folder lives.
- **The 21 `@/` imports** in the frontend — alias behavior is preserved (see §6).

## 6. Configuration changes

This is the part that requires care. The key insight: the frontend configs use **relative** paths, so moving them (and the directories they reference) together keeps everything valid.

| File | Change | Rationale |
|---|---|---|
| `client/vite.config.ts` | **None.** `@` alias is `path.resolve(__dirname, '.')` and `loadEnv(mode, '.', '')` — both relative to the config file. After the move they resolve to `client/`, where `components/`, `hooks/`, `lib/` now live. | All 21 `@/` imports continue to resolve. |
| `client/tsconfig.json` | **None.** `include: ["src", "components", "hooks", "lib"]` and `paths: { "@/*": ["./*"] }` are relative. | Valid relative to `client/`. |
| `client/index.html` | **None.** References `/src/main.tsx`. | Vite serves `client/` as root. |
| `client/components.json` | **None.** shadcn aliases point at `@/components` etc., which resolve via the preserved `@` alias. | Preserved alias keeps shadcn working. |
| `client/package.json` | **Prune** `express`, `pg`, `@types/pg`, `@types/express`. **Keep** `@google/genai` (imported by `src/services/gemini.ts`) and all genuinely-used deps. | Verified: no `src` file imports the pruned packages. |

## 7. Environment variable split

The current root `.env.example` mixes backend and frontend variables. After separation, each application owns its own `.env.example`:

- `server/.env.example` — backend variables:
  - `DATABASE_URL`
  - `AGENT_PROVIDER` (`claude` or `opencode`)
  - `AGENT_TIMEOUT_MS`
  - `PORT` (`8000`)
- `client/.env.example` — frontend variables:
  - `GEMINI_API_KEY` (used client-side by `src/services/gemini.ts`, injected via `define` in `vite.config.ts`)

The actual root `.env` (gitignored) is removed; each app reads its own `.env` from its own directory (Vite via `loadEnv('.', ...)`, FastAPI via `load_dotenv()` in `server/main.py`).

## 8. Root `.gitignore`

Existing patterns are written without a leading `/`, so they match at any depth and already cover the new layout:

- `node_modules/` → covers `client/node_modules/`
- `dist/` → covers `client/dist/`
- `.env*` (with `!.env.example`) → covers both `client/.env*` and `server/.env*`
- `meetily/`, `multica/`, `xone/`, `.venv/`, `tools/` → unchanged

**Result:** no functional change required to `.gitignore`. The stale `build/`/`coverage/` entries may be left as-is.

## 9. Root `README.md`

Rewrite the "Run Locally" section to document the two-app setup:

```bash
# Backend (Python/FastAPI)
cd server
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # set DATABASE_URL, AGENT_PROVIDER
.venv/bin/uvicorn main:app --port 8000 --reload

# Frontend (Vite + React)
cd client
npm install
cp .env.example .env   # set GEMINI_API_KEY if using client-side AI
npm run dev            # http://localhost:3000, proxies /api & /asr to the backend
```

## 10. How to run (after migration)

```bash
# Backend — unchanged
cd server && .venv/bin/uvicorn main:app --port 8000 --reload

# Frontend
cd client && npm install && npm run dev   # :3000, proxies /api & /asr to backend
```

## 11. Verification

1. `cd client && npm run lint` (`tsc --noEmit`) passes with no new errors versus the pre-move state.
2. `cd client && npm run build` succeeds and emits `client/dist/`.
3. `cd client && npm run dev` boots on `:3000`; a request to `/api/...` is proxied to the backend on `:8000`.
4. `cd server && .venv/bin/uvicorn main:app --port 8000` starts unchanged.
5. `git status` shows the moves as renames (preserves history) for the moved files.

## 12. Out of scope

- No changes to backend (`server/`) code, deps, or config.
- No monorepo workspace tooling (no root orchestrator / `npm run dev` that starts both) — explicit decision.
- No full dependency audit beyond pruning the four confirmed-unused backend packages.
- No splitting into separate repositories.
- No change to the reference repos (`meetily/`, `multica/`, `xone/`) — they remain gitignored.
